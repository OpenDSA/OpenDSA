Writing FA Exercises

How to add a DFA or NFA construction exercise to OpenFLAP: the files involved, the exercise JSON, and the answer key.

Covers exercises graded by AV/OpenFLAP/exercises/exerController/FAGrader.js. PDA, TM, grammar, minimization and NFA-to-DFA exercises work differently and are not covered here. DRAFT — [author / date].

1. How FA exercises are graded

The student builds a machine in the exercise editor and submits it. The grader compares it with the exercise's answer key, a .jff file:

  • The answer is correct when the student's machine accepts exactly the same strings as the answer key. It does not need to look like the key: any number of states, any layout, DFA or NFA (unless the exercise asks for a DFA).
  • When it is wrong, the student is told the shortest string the two machines disagree on, e.g. "Not yet: your machine accepts bbbb, but it should reject it."
  • On a "DFA" exercise, an answer with a λ-transition or two transitions on the same symbol from one state is rejected with "Your answer must be a DFA, not an NFA."
  • The score is 1 for a correct answer and 0 otherwise.

The exercise's test cases are shown to the student as examples, with their machine's result for each, but they do not affect the score. A machine can pass every example and still be wrong.

The answer key is the only definition of the right answer. If the key is wrong, every student is graded against the wrong language, so check it (section 4) before the exercise goes into a book.

3. The exercise JSON

The file holds an array with one exercise object. A shortened version of DFAodda.json:

[{
  "exerciseType": "DFA",
  "containLetters": ["a", "b"],
  "tools": ["edit", "addState", "addTransition", "delete", "undo", "redo"],
  "description": "Give a DFA that accepts the language over $\\Sigma = \\{a, b\\}$ of strings with an odd number of a's.",
  "testCases": [
    { "a": true, "ShowTestCase": true },
    { "aa": false, "ShowTestCase": true },
    { "": false, "ShowTestCase": true }
  ],
  "graph": { "nodes": [], "edges": [] },
  "solution": "../../../machines/FA/DFAodda.jff"
}]
FieldMeaning
exerciseType"DFA" or "NFA". This is what sends the exercise to the FA grader. "DFA" also rejects nondeterministic answers; use "NFA" when any machine for the language is acceptable.
descriptionThe question shown to the student. Text between a pair of $ signs is LaTeX, rendered as an image. Backslashes must be doubled inside JSON strings (\\Sigma, \\{); a single \b, \n or \t is a JSON escape for a control character, not LaTeX.
containLettersThe input alphabet. The trap-state tools use it to decide which transitions are missing, so it must list every symbol of the language, including ones a correct machine might only use to reach a trap state.
toolsThe toolbar buttons, in order. An exercise gets exactly these, and none if the field is missing. A book can override the list with a tools URL parameter, e.g. ?tools=edit,addState,addTransition. Names are listed below.
testCasesExample strings shown to the student after they submit. Each entry is { "<string>": true|false, "ShowTestCase": true }, where true means the string is in the language. Use "" for the empty string (shown as λ). An entry without "ShowTestCase": true is not shown. Examples do not affect the score, but they help students see what is wrong, so include a few short strings on both sides of the language.
graphThe machine the student starts with. Leave it empty ({ "nodes": [], "edges": [] }) for construction exercises.
solutionPath to the answer key, relative to the exercise page. For pages in exercises/FLAssignments/<folder>/ this is "../../../machines/FA/<name>.jff". Required: an exercise without one cannot be graded.

Tool names

NameButton
editEdit states and transitions
addStateAdd states
addTransitionAdd transitions
deleteDelete states and transitions
undo, redoUndo and redo
addTrapStateAdd a state labeled "Trap State"
highlightIncompleteHighlight states missing a transition on some symbol of containLetters
completeWithTrapAdd a trap state and every missing transition. This does the main step of a complement exercise for the student, so the complement exercises leave it out.
highlightNDHighlight nondeterministic states

The usual set is ["edit", "addState", "addTransition", "delete", "undo", "redo"]. Complement exercises add "addTrapState", "highlightIncomplete", "highlightND".

Older exercise files had totalTrueCases, totalFalseCases, randomStringLength, type and _exerciseType. These were for generating random hidden test cases, which FA exercises no longer use. Leave them out of new DFA and NFA exercises.

4. The answer key (.jff)

The answer key is a finite automaton for the exercise's language, saved in JFLAP's .jff format (see JFLAP File Format). Put it in AV/OpenFLAP/machines/FA/.

  • It can be a DFA or an NFA, and it does not need to be minimal or complete. Only the language it accepts matters.
  • Its alphabet should match containLetters.
  • Make it in the FA editor (AV/OpenFLAP/FA.html) and save it, or in JFLAP 7.1. Files from either work.
  • After saving, open the file and check that every transition you drew is there, self-loops included.

Checking the key

Before the exercise goes into a book, open its page and submit:

  1. The key itself (rebuilt in the exercise editor). Expected: "Correct: your machine accepts exactly the strings in the language."
  2. One initial, non-final state with no transitions (a machine that accepts nothing). Expected: "Not yet: your machine rejects X, but it should accept it.", where X is the shortest string in the language (λ if the empty string is in it). If X is not the shortest string you expect, the key is wrong.
  3. A machine with one mistake you expect students to make. The message should name a string that really shows the mistake.

Every example in testCases should also show green when you submit the key. A red example means the example or the key is wrong.

"This answer could not be graded" means the key failed to load: check the solution path and that the file is a fa type .jff.

5. The exercise page

Copy an existing page such as FA/DFAodda.html and change three things:

  • The JSON path returned by getExerciseLocation.
  • The <title>. Give each exercise its own title, e.g. DFA Exercise: Odd a.
  • The Title: and Description: lines in the comment at the top.

The page loads FAExTemplate.html, which includes FAGrader.js. A page that does not use the template must include exercises/exerController/FAGrader.js itself, before ExerciseController.js, or its exercise falls back to the old test-case grading.

6. Adding it to a book

.. avembed:: AV/OpenFLAP/exercises/FLAssignments/FA/DFAodda.html pe
   :long_name: Odd number of a's
   :keyword: Finite Automata; Deterministic Finite Acceptor

Give each exercise in a module its own :long_name:. Points are set in the book's config file, keyed by the page's file name ("DFAodda": { "points": 1.0 }), so renaming the page later also means updating the config.

7. Checklist

  • exerciseType is "DFA" or "NFA".
  • solution points to the answer key, and the key accepts exactly the language in description.
  • containLetters lists the whole alphabet.
  • The examples include short strings both in and out of the language, and all show green against the key.
  • description renders correctly, LaTeX included.
  • The page has its own <title>, and the book's :long_name: is unique in its module.
  • The three key checks in section 4 give the expected messages.
