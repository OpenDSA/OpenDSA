1. Overview

A .jff file is a plain XML document. JFLAP also opens files ending in .xml with the same reader. Every file has the same outer shape: a root element <structure> whose first child, <type>, says what the file contains. The rest of the content depends on the type.

<?xml version="1.0" encoding="UTF-8" standalone="no"?>
<!--Created with JFLAP 7.1.-->
<structure>
    <type>fa</type>
    ... content for this type ...
</structure>

The XML comments JFLAP writes (Created with JFLAP 7.1., The list of states., and so on) are for people reading the file. JFLAP ignores them when it opens a file, and they can be left out.

This XML format was introduced in JFLAP 4. Older JFLAP 3 text files and JFLAP 4 beta serialized files use different formats and are not covered here.

2. File types

The text inside <type> is one of:

<type>ContentsSection
faFinite automaton (DFA or NFA)4
pdaPushdown automaton5
turingTuring machine, one to five tapes6
turingbbTuring machine with building blocks7
mealyMealy machine8
mooreMoore machine8
grammarGrammar9
reRegular expression10
lsystemL-system11
regular pumping lemmaSaved regular pumping lemma game12
context-free pumping lemmaSaved context-free pumping lemma game12

The first six types are all automata and share one structure, described next. They differ only in what is written on a transition (and, for Moore machines, on a state).

3. Automata: states, transitions and notes

For every automaton type, the <type> element is followed by an <automaton> element containing the states, then the transitions, then any notes.

<structure>
    <type>fa</type>
    <automaton>
        <state id="0" name="q0"> ... </state>
        <state id="1" name="q1"> ... </state>
        <transition> ... </transition>
        <note> ... </note>
    </automaton>
</structure>

If the <automaton> wrapper is missing, JFLAP looks for states and transitions directly inside <structure>, so files from older versions that omit it still open.

3.1 <state>

<state id="0" name="q0">
    <x>60.0</x>
    <y>144.0</y>
    <label>start here</label>
    <initial/>
    <final/>
</state>
ItemKindRequiredMeaning
idattributeyesInteger that identifies the state. Transitions refer to states by this number. Must be unique.
nameattributenoName shown in the state circle. Defaults to q followed by the id (e.g. q3). A <name> child element is also accepted and takes priority over the attribute.
<x>, <y>elementnoPosition of the state's center on the canvas, in pixels, as decimal numbers. If any state has no position, JFLAP lays out the unpositioned states automatically when the file is opened.
<label>elementnoOptional label text displayed under the state.
<initial/>empty elementnoPresent if this is the start state. Only one state should have it; if several do, the last one read becomes the start state.
<final/>empty elementnoPresent if this is an accepting (final) state. Any number of states may have it.

3.2 <transition>

<transition>
    <from>0</from>
    <to>1</to>
    <controlx>170</controlx>
    <controly>90</controly>
    ... type-specific elements ...
</transition>
ElementRequiredMeaning
<from>yesThe id of the source state.
<to>yesThe id of the destination state. May equal <from> (a loop).
<controlx>, <controly>noInteger control point for a curved edge. Both must be present to take effect. If absent, JFLAP draws the edge with its default shape.

Each transition holds exactly one label. A transition with several labels in the editor (for example a, b on the same arrow) is saved as several separate <transition> elements with the same <from> and <to>.

The type-specific elements are described in sections 4 to 8.

Empty strings and λ. An empty element such as <read/> means the empty string, which JFLAP displays as λ (or ε, depending on preferences). A missing element is treated the same as an empty one. The λ character itself is never written to the file.

3.3 <note>

A text note placed on the canvas.

<note>
    <text>Accepts strings ending in ab</text>
    <x>40.0</x>
    <y>300.0</y>
</note>

<text> is required; a note without it is skipped. <x> and <y> give its position.

4. Finite automata (fa)

Each transition has one extra element:

ElementMeaning
<read>The input read on this transition. Empty for a λ-transition. May contain more than one character (JFLAP allows multi-character labels on FA transitions).

Complete example: an NFA over {a, b} that accepts strings containing a, with a λ-transition.

<?xml version="1.0" encoding="UTF-8" standalone="no"?><!--Created with JFLAP 7.1.--><structure>
    <type>fa</type>
    <automaton>
        <!--The list of states.-->
        <state id="0" name="q0">
            <x>60.0</x>
            <y>144.0</y>
            <initial/>
        </state>
        <state id="1" name="q1">
            <x>278.0</x>
            <y>152.0</y>
        </state>
        <state id="2" name="q2">
            <x>494.0</x>
            <y>162.0</y>
            <final/>
        </state>
        <!--The list of transitions.-->
        <transition>
            <from>0</from>
            <to>0</to>
            <read>b</read>
        </transition>
        <transition>
            <from>0</from>
            <to>1</to>
            <read>a</read>
        </transition>
        <transition>
            <from>1</from>
            <to>2</to>
            <read/>
        </transition>
        <transition>
            <from>2</from>
            <to>2</to>
            <read>a</read>
        </transition>
        <transition>
            <from>2</from>
            <to>2</to>
            <read>b</read>
        </transition>
    </automaton>
</structure>

5. Pushdown automata (pda)

Each transition has three extra elements, always written in this order:

ElementMeaning
<read>Input read. Empty for λ.
<pop>String popped from the top of the stack. Empty to pop nothing.
<push>String pushed onto the stack. Empty to push nothing.

The editor shows this transition as a, Z ; aZ:

<transition>
    <from>0</from>
    <to>0</to>
    <read>a</read>
    <pop>Z</pop>
    <push>aZ</push>
</transition>

The initial stack symbol (Z by default) is not stored in the file.

6. Turing machines (turing)

6.1 Single-tape

Each transition has three extra elements:

ElementMeaning
<read>Symbol read from the tape. Empty means the blank symbol.
<write>Symbol written to the tape. Empty means the blank symbol.
<move>Head movement: R (right), L (left) or S (stay). If missing, JFLAP uses R.
The blank symbol. JFLAP displays the blank as □ (Unicode U+25A1), but always saves it as an empty element, e.g. <read/>. The □ character does not appear in files.

The editor shows this transition as a ; x, R:

<transition>
    <from>0</from>
    <to>1</to>
    <read>a</read>
    <write>x</write>
    <move>R</move>
</transition>

6.2 Multi-tape

A machine with 2 to 5 tapes adds a <tapes> element, placed between <type> and <automaton>. Each <read>, <write> and <move> then carries a tape attribute (numbered from 1). JFLAP writes them grouped by tape: read, write, move for tape 1, then for tape 2, and so on.

<structure>
    <type>turing</type>
    <tapes>2</tapes>
    <automaton>
        ...
        <transition>
            <from>0</from>
            <to>1</to>
            <read tape="1">a</read>
            <write tape="1">a</write>
            <move tape="1">R</move>
            <read tape="2"/>
            <write tape="2">a</write>
            <move tape="2">R</move>
        </transition>
    </automaton>
</structure>

A missing tape attribute means tape 1. Missing <tapes> means one tape. More than 5 tapes is rejected.

7. Turing machines with building blocks

A building block is a state that contains a whole Turing machine. In a file saved from the building-blocks editor:

  • Every state is written as a <block> element instead of <state>, even states that are not really blocks. A <block> has the same id, name, <x>, <y>, <initial/> and <final/> as a state, plus a <tag> element.
  • <tag> holds the name of the element that stores the machine inside the block. JFLAP generates these as Machine followed by the id (e.g. Machine2).
  • Each inner machine is written as a separate element with that name, placed directly inside <structure>, next to <automaton>. Its contents have the same form as <automaton>. Ordinary states get an empty inner machine.
  • A transition can be marked block="true". Such a transition only stores <read> (for tape 1); its write and move are fixed by JFLAP.
<structure>
    <type>turingbb</type>
    <automaton>
        <block id="0" name="q0">
            <tag>Machine0</tag>
            <x>80.0</x>
            <y>100.0</y>
            <initial/>
        </block>
        <block id="1" name="q1">
            <tag>Machine1</tag>
            <x>240.0</x>
            <y>100.0</y>
            <final/>
        </block>
        <transition>
            ...
        </transition>
    </automaton>
    <Machine0/>
    <Machine1>
        ... states and transitions of the machine inside q1 ...
    </Machine1>
</structure>

When reading, JFLAP looks up an inner machine by searching the whole document for the first element whose name equals the <tag> text. Tag names should therefore be unique within a file.

Any file containing a <block> element is opened as a building-block machine, whatever its <type> says. See section 13.

8. Mealy and Moore machines

8.1 Mealy (mealy)

Output is produced on transitions. Each transition has two extra elements:

ElementMeaning
<read>Input read.
<transout>Output produced when the transition is taken.
<transition>
    <from>0</from>
    <to>1</to>
    <read>a</read>
    <transout>1</transout>
</transition>

8.2 Moore (moore)

Output belongs to states. Each <state> has an extra <output> element:

<state id="1" name="q1">
    <x>200.0</x>
    <y>100.0</y>
    <output>1</output>
</state>

Transitions are written like Mealy transitions, including <transout>, which JFLAP sets to the output of the destination state.

Watch out: when reading a Moore file, each transition's <transout> overwrites the <output> of its destination state, because transitions are read after states. Files written by other tools should make every incoming transition's <transout> equal to the destination state's <output>. A missing <transout> counts as empty and will clear the state's output.

9. Grammars (grammar)

A grammar is a list of <production> elements placed directly inside <structure> (there is no wrapper element). Each production has a left side and a right side.

<structure>
    <type>grammar</type>
    <!--The list of productions.-->
    <production>
        <left>S</left>
        <right>aSb</right>
    </production>
    <production>
        <left>S</left>
        <right/>
    </production>
</structure>
ElementMeaning
<left>Left-hand side, e.g. S. May be more than one symbol for unrestricted grammars.
<right>Right-hand side. Empty for a λ-production (S → λ).

The grammar's kind (regular, context-free, unrestricted) and its start variable are not stored explicitly. By JFLAP convention the start variable is the left side of the first production, so keep that production first. Duplicate productions are dropped when the file is opened.

10. Regular expressions (re)

<structure>
    <type>re</type>
    <!--The regular expression.-->
    <expression>(a+b)*abb</expression>
</structure>

The expression is stored as the text typed in the editor. In JFLAP's notation + means union, * is Kleene star, and concatenation is written by juxtaposition.

An empty <expression/> element causes an error when opening the file. To save an empty expression, omit the element entirely.

11. L-systems (lsystem)

An L-system has an axiom, rewriting rules and drawing parameters, all directly inside <structure>. Symbols are separated by spaces.

<structure>
    <type>lsystem</type>
    <!--The L-system axiom.-->
    <axiom>F</axiom>
    <!--The rewriting rules.-->
    <production>
        <left>F</left>
        <right>F + F - - F + F</right>
    </production>
    <!--The drawing parameters.-->
    <parameter>
        <name>angle</name>
        <value>60</value>
    </parameter>
</structure>
ElementRequiredMeaning
<axiom>yesStarting string. If there are several, the last one is used.
<production>noOne <left> symbol and one or more <right> replacements. Several <right> elements make a stochastic rule (one is chosen at random).
<parameter>noA <name> / <value> pair, e.g. angle, distance. Parameters without a name are ignored.

12. Pumping lemmas

These files save the state of a pumping lemma game. All elements are placed directly inside <structure>.

12.1 Regular (regular pumping lemma)

<structure>
    <type>regular pumping lemma</type>
    <name>...language name as shown in JFLAP...</name>
    <first_player>...</first_player>
    <m>3</m>
    <w>aaabbb</w>
    <i>2</i>
    <xLength>1</xLength>
    <yLength>1</yLength>
    <attempt>...</attempt>
</structure>
ElementMeaning
<name>Which language/lemma this is. Must match one of the lemmas built into JFLAP.
<first_player>Human or Computer: who moves first.
<m>, <w>, <i>The values of m, w and i chosen during the game.
<xLength>, <yLength>Lengths of x and y in the decomposition w = xyz.
<attempt>Zero or more previous attempts, in order.

12.2 Context-free (context-free pumping lemma)

The same elements as the regular version, except that the decomposition w = uvxyz is stored as <uLength>, <vLength>, <xLength> and <yLength>. It may also contain any number of <case> elements, each recording one case of the proof:

<case>
    <caseULength>0</caseULength>
    <caseVLength>1</caseVLength>
    <caseXLength>0</caseXLength>
    <caseYLength>1</caseYLength>
    <caseI>2</caseI>
</case>

13. How JFLAP reads a file

These rules matter mostly to people writing tools that produce .jff files.

13.1 Choosing the file type

JFLAP checks the following, in order, and stops at the first match:

  1. If the file contains a <tapes> element anywhere, it is opened as a (multi-tape) Turing machine.
  2. Otherwise, if it contains a <block> element anywhere, it is opened as a Turing machine with building blocks.
  3. Otherwise the text of the first <type> element is used. A file without <type> cannot be opened.
  4. For <type>turing</type>, JFLAP asks the user whether to open it as a standard Turing machine or as one with building blocks.

13.2 Leniency and errors

SituationWhat JFLAP does
Unknown elementsIgnored. Extra elements can be added without breaking JFLAP.
Missing transition fields (<read>, <pop>, etc.)Treated as empty (λ or blank). Missing <move> becomes R.
State with no <x>/<y>Opened and placed automatically.
Two states with the same idError; the file does not open.
Transition with no <from> or <to>, or referring to an id that does not existError; the file does not open.
id that is not an integerSilently read as -1. Avoid this: two such states collide.
Coordinate that is not a numberError; the file does not open.
Turing machine with fewer than 1 or more than 5 tapes, or a tape attribute out of rangeError; the file does not open.

13.3 Writing

  • JFLAP writes UTF-8, with tab indentation.
  • States are written in their internal order, which is usually but not always increasing id. Transition order is not significant.
  • <x> and <y> are always written as decimals (e.g. 60.0).
